# v0.8.11 方案：时值模式连续播放指示线

日期：2026-10-30
状态：待实施

## 1. 目标与范围

在「时值排版」播放时显示一条横向连续移动的竖线，表示当前演奏拍点。长音、休止和延长线期间仍连续前进；换行、谱面反复和 A/B 循环时跳到对应位置。双声部使用同一条贯穿联谱的线。

保留音符高亮和现有手动浏览/恢复跟随交互。自然排版、小节对齐暂不启用连续线。不新增语法，不修改音符时值或音源契约。本次只写方案，不修改实现、版本号或提交 commit。

## 2. 现状与缺口

- `packages/core/src/renderer/time-layout.ts` 已按全谱统一 `pixelsPerBeat` 布局，音符包含记谱 `startBeat`；但比例、起音偏移 `inset` 和时间轴端点仍是函数内部数据。
- `packages/core/src/player/contracts.ts` 的 `BeatTransport.beat` 已提供四分音符拍时钟。Web 的 `apps/web/src/adapters/audio/synth.ts` 通过 Transport ticks / PPQ 实现，不需要再引入独立计时器。
- core Player 目前通过 `onNoteHighlight` 在事件边界传递音符索引，不能提供音符内部的连续进度。双声部已有的竖条位于最近活动音符，仍是离散跳动。
- 实际谱面实现在 `packages/score-view/src/ScoreView.tsx`，Web 同名组件只是转导出。现有横向跟随以音符坐标为目标，长音中不会持续更新。
- Scheduler 已保留 `writtenStartBeat`、`writtenMeasureStartBeat`、`measureOccurrence`，并支持选段归一化。演奏拍数经过反复展开后不能直接用作记谱拍数。

## 3. 分层设计

数据流：`BeatTransport → Player 播放位置快照 → 应用注入读取入口 → ScoreView 动画层 → Renderer 坐标映射`。

### 3.1 Player：暴露音乐位置，不暴露坐标

新增平台无关的只读 `PlaybackPosition` 和 `Player.getPlaybackPosition()`（名称可在实施时按现有导出规范调整）。快照至少包含：播放状态、阶段（等待/播放/结束）、会话标识、演奏拍点、原谱拍点、原谱小节及该小节的演奏 occurrence；位置未建立时返回空值。

- 读取实际 Transport 拍点，扣除 `playbackDelayBeats`，不使用 `Date.now()` 或“已播放秒数 × 当前 BPM”。变速后位置连续，暂停时冻结。
- 构建独立的小节演奏区间表：每段保存演奏起止拍、原谱起止拍、小节身份及 occurrence。由调度时的小节顺序及选段结果生成，按演奏拍点二分查找，再以小节内偏移映射回原谱。
- 映射不选取“最近发声事件”：倚音/波音可能提前发声，同音连线可能合并发声，双声部同拍存在多个事件。区间表应从小节时序构建，避免重复音乐规则；需要抽取公共时间数据时放在独立音乐纯函数模块，Renderer 不导入 Player。
- A/B 选段使用归一化后的演奏起点和原谱小节起点映射，不能遗漏 segment 的起点偏移。Transport 循环回绕后直接读取当前拍点，不靠前后帧拍数递增推断 occurrence。
- 小节区间使用左闭右开；精确到达边界进入下一小节，曲末另行处理。倒计时/播放延迟期间不移动；起始倚音阶段停在主音起点，正文从第一个记谱拍点开始。
- 停止、换谱、销毁使会话失效；异步初始化完成后也不得复活旧位置。读取位置不得初始化音频或产生调度副作用。

### 3.2 Renderer：提供显式时间几何

为时值布局增加可选的只读时间几何数据，例如每个小节记录 `startBeat`、`endBeat`、`originX`、`pixelsPerBeat`、所属谱行；行数据提供指示线纵向范围。其他排版不提供该数据，兼容已有消费者。

纯函数 `resolveTimeCursor(layout, writtenPosition)` 返回 `{ lineIndex, x, top, bottom } | null`，只依赖布局及音乐位置值，不读取时钟、DOM 或应用状态。

横坐标为 `originX + (writtenBeat - startBeat) * pixelsPerBeat`。其中 `originX` 必须来自布局的 `measure.x + inset`，不能直接取小节线，也不能从前后两个音符插值；附件有横向偏移且末音后仍有完整时值。

时间轴终点按同一公式计算，必要时纳入 SVG 宽度和留白，避免末拍或行末光标裁切。换行边界直接切至下一行起音坐标，不在两行之间做斜向动画。纵向范围复用布局计算，覆盖双声部及歌词区域，不在组件中重新猜测字号间距。空谱、零时值小节和无效拍点返回空值，不产生除零或无效坐标。

### 3.3 共享谱面：隔离动画与静态谱面

`ScoreView` 增加可选的只读位置读取入口，例如 `readPlaybackPosition?: () => PlaybackPosition | null`，由 Web 组合层传入稳定函数。共享包只依赖公开类型，不依赖 Zustand、Web Player 实例或 Tone.js；未接入入口的消费者保持原表现。

将 RAF 循环封装在小型 `PlaybackCursor`/hook 中。播放且为 time 模式时逐帧读取快照并解析坐标，只更新指示线局部状态；静态音符树和 layout 保持 memo 化。暂停时保留位置并取消循环，恢复时重启；停止/结束隐藏。显隐和暂停位置由一次状态同步更新，不能依赖 RAF 继续运行。

优先采用局部 React 状态和 SVG `<line>`；不把每帧拍数写入全局 store，不触发整页重渲染。若性能验收确认需要命令式更新，仅在独立动画组件内通过 React ref 修改该线的 transform，并保留完整清理逻辑。

线放在谱面相同坐标组中，统一应用 `scoreOffset`，避免重复加偏移。使用主题色、细线和 `pointerEvents="none"`，不遮挡点击或增加逐帧读屏播报。时值模式下用连续线替代已有双声部离散竖条，避免出现两条播放线。

## 4. 跟随、生命周期与时钟精度

- 横向可见性改以连续线为依据，线进入视口边缘安全区时调整 scrollLeft；保留现有跟随开关与用户操作后的暂停跟随，线自身仍继续移动。
- 纵向跟随只在谱行变化时触发。编辑器定位仍走现有入口。自动滚动只有越界时执行，不能每帧启动新的 smooth scroll；循环/反复/换行立即定位，避免扫过中间内容。
- 复用一个指示线位置结果供绘制与跟随消费，避免两套 RAF 和不同的定位算法。
- resize、字号和布局变化后用当前播放快照重新映射，不重启音乐。组件卸载、模式切换、停止及会话替换必须取消 RAF 并清除旧引用。
- 页面进入后台暂停视觉 RAF；恢复可见时读取当前 Transport 重新定位，不补跑历史帧。
- 实施时检查当前 Tone 适配器的 ticks 读取与 Draw 高亮所用音频时刻是否一致。若 lookAhead 导致可见提前，在适配器内增加与播放呈现时刻一致的拍点读取端口，并同步调整其他 runtime 与测试替身；不能在组件里写固定毫秒补偿。通过真实浏览器音画检查决定是否需要扩展，不能只根据 mock 推断同步准确。

## 5. 实施顺序

1. 明确位置快照与时间几何契约，提取/复用纯音乐小节时序，验证反复与选段映射。
2. Player 增加快照读取及会话失效处理，沿用现有 runtime 注入机制；不改变音色接口。
3. 时值布局导出几何并增加纯坐标解析函数，覆盖行末、终点和双声部。
4. 共享 score-view 接入独立动画层；Web EditorPage 注入读取入口，整合横向跟随。
5. 核查 minitool 等共享消费者的兼容性，补充排版帮助说明并执行验收。

## 6. 验证与完成标准

- 纯函数测试：混合时值、附点、休止、延长线中点、起始附件、空谱、零时值小节、弱起、行末/曲末和双声部共享坐标。验证连续一拍移动距离等于布局每拍宽度。
- Player 使用可控 BeatTransport 测试：延迟、暂停恢复、变速、正常结束、会话替换、谱面反复第二遍、A/B 起点非零和多轮回绕。无需真实等待或依靠墙钟断言。
- 组件使用可控 RAF 验证暂停/停止/切换/卸载的清理，布局变更后重映射，未注入入口的兼容行为。确认每帧不会更新全局 store 或重渲染整个谱面。
- 浏览器实际播放：桌面与 390px，长音和休止期间连续移动；起音与线经过数字位置同步；播放中变速无跳点，暂停冻结，恢复连续，换行和反复即时跳转。
- 检查双声部、静音某声部、多段歌词、过宽小节、手动横向浏览和恢复跟随；歌词/符号不裁切，线不阻挡操作。后台返回定位正确，反复切换无残留动画。
- 实施后运行 `pnpm lint`、`pnpm build:core`、`pnpm test`、`pnpm build:web`、`pnpm build:minitool`，记录浏览器验收结果。本文档变更本身不需要运行代码测试。
