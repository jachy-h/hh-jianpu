# v0.8.0 共享模块与平台适配

Web 和小红书 H5 都消费三个 workspace 包：`@hh-jianpu/core`、`@hh-jianpu/score-view`、`@hh-jianpu/score-library`。应用之间没有导入关系，core 不依赖另外两个包；`pnpm check:boundaries` 检查此边界。

Core 保留 Parser、AST、布局、移调、Scheduler、共享 Player 编排以及纯函数 session 选择器。`PlaybackRuntime` 注入按拍计时、UI 到时通知、音源加载、节拍点击、预备拍等待和销毁；所有实际节点及平台计时位于适配器中。音源的 noteOn/noteOff、唯一发声 ID、实际发声拍数、反复、选段和双声部规则由同一套 core 代码确定。

Web 的 Tone 适配位于 `apps/web/src/adapters/audio`；H5 的原生 Web Audio/主线程前瞻时钟位于 `apps/minitool/src/adapters/audio`。H5 时钟提前 100ms 提交音频事件，每 25ms 唤醒一次。变速时锚定当前音乐拍点，同时重新安排已提交但尚未发生的节点起音、释放和 UI 通知。页面离开前台时 H5 停止播放。

`score-view` 接收 Score 与受控回调，不访问应用 store、路由或音频；组件样式随包提供。无 ResizeObserver 时监听窗口 resize，无元素 scrollTo 时直接更新 scrollTop。

`score-library` 是内置资源的唯一来源，目录见 [资源维护说明](../score-library.md)。JSONC 转换、ID/配置校验发生在构建期；应用消费静态 ESM 数据。音乐语义用构建后的 core 统一校验，不在 core 内建立资源依赖。

## 播放 API 迁移

原先从 core 导入的无参数 `Player` 和 Tone 采样工厂已调整：

```ts
// Web 应用内部：保留原音色配置和默认合成音构造习惯。
import { Player } from '../adapters/audio/synth';
import { createSampleInstrument } from '../adapters/audio/instruments';

// 独立使用 core：调用者必须明确注入运行时和音色列表。
import { Player } from '@hh-jianpu/core';
const player = new Player({
  instruments: [{ id: 'triangle', label: '合成音' }],
  runtime: async () => createApplicationRuntime(),
});
```

上述 runtime 工厂由调用应用提供；core 不再运行时加载 Tone，也不导出依赖 Tone 节点的音色工厂。`InstrumentNote`、`PlaybackInstrument`、`InstrumentBank` 和 `PlaybackRuntime` 是平台无关类型。此前直接消费 core 音频工厂的外部代码需要显式迁移，这属于 v0.8.0 的 API 变化。

## 构建与开发

CI 通过工作流安装 pnpm 9；项目不设置 `packageManager` 版本锁定，本地开发直接使用已安装的 pnpm。`verifyDepsBeforeRun: warn` 将依赖安装保留为显式操作。`pnpm build:shared` 生成 core 声明、资源及谱面组件，并校验所有启用资源。`pnpm build:web` / `pnpm build:minitool` 会先构建这些共享包。`pnpm dev` / `pnpm dev:web`（5173）与 `pnpm dev:minitool`（5174）会直接调用 Node 启动脚本，输出共享包构建进度并监听源文件及资源目录。`pnpm dev:all` 用一组监听同时启动两端，避免重复监听。启动脚本直接调用已安装的 TypeScript/Vite，不嵌套调用另一份 pnpm；缺依赖或端口占用会明确退出。

H5 的生产入口是单一 IIFE 经典脚本；开发页仍使用 Vite 模块协议。`apps/minitool/tests` 和音频实验产物都不进入正式小工具 ZIP。`pnpm audit:minitool` 检查最终 dist；`pnpm package:minitool` 构建、校验并输出上传包及摘要。
