## 2. 教学依据与表达边界

教学中应区分三个层次：稳定脉冲（何时到下一拍）、拍型（几拍构成一组）、节奏（拍内音符如何分布）。本组件首版表达前两个层次，不跟随旋律音符改变小球的击拍频率。

- 上下击拍：下击、击点、抬起组成循环，可以用于不同拍号，不专属于 4/4。
- 二拍指挥：下、上。
- 三拍指挥：下、外、上，整体接近带回弹的三角形。
- 四拍指挥：下、内、外、上，不能用单个 V 形代替完整四拍结构。
- 图式存在教学与动作风格差异；首版是适合跟拍的简化教学图式，不宣称唯一标准或专业指挥动作复刻。

参考资料：

- [人教一年级音乐教学设计](https://www.pep.com.cn/rjyy/jxzy/ja/202410/W020241018572909063518.pdf)：均拍、踏步、拍抬和指挥图式练习。
- [Macalester：Simple meters / Conducting patterns](https://pressbooks.macalester.digital/multimodalmusicianship/chapter/simple-meters/#conducting-patterns)：二、三、四拍动作顺序与弹性下击。
- [YourClassical：What is steady beat?](https://www.classnotes.org/story/2020/04/16/what-is-steady-beat)：通过身体动作建立稳定拍感。

以下坐标、曲线、回弹比例与高亮时长为产品设计参数，须经实际跟拍验证，不是教材给出的标准数值。

## 4. 输入输出契约

首版拍号限定为 2/4、3/4、4/4，BPM 明确定义为每分钟四分音符数。暂不接受 6/8 或用分子直接推断复拍子的指挥拍数；将来需单独加入速度单位及分组模型。

```ts
interface Meter {
  readonly beatsPerBar: 2 | 3 | 4;
  readonly beatUnit: 4;
}

interface BeatSnapshot {
  readonly positionBeats: number; // 从第 1 小节第 1 拍起算，0 是第 1 拍拍点
  readonly bpm: number;
  readonly status: 'stopped' | 'playing' | 'paused';
  readonly revision: number;      // 跳转、重置、循环回绕时递增
}

interface BeatSource {
  read(): BeatSnapshot;           // 播放时每帧读取权威位置，不能只返回上次整数拍
  subscribe(listener: () => void): () => void; // 状态变化唤醒，暂停时也能响应 seek
}

interface BeatVisualizerProps {
  readonly meter: Meter;
  readonly source: BeatSource;
  readonly mode: 'bounce' | 'conducting';
  readonly mirrored?: boolean;
  readonly showGuide?: boolean;
  readonly showBeatNumbers?: boolean;
  readonly scrolling?: boolean;   // 仅 bounce 生效
  readonly reducedMotion?: 'system' | 'always' | 'never';
  readonly className?: string;
  readonly label?: string;
}
```

主题和尺寸参数另用明确类型补充；避免公开内部 SVG 控制点作为首版稳定 API。`createBeatClock({ bpm, now })` 返回实现 BeatSource 的时钟及 play/pause/stop/seek/setTempo 方法；最简使用无需播放器。组件读 source，不负责修改它，不再同时接收另一套 bpm/position props。

纯计算入口输出 `BeatFrame`：小节序、0-based 拍索引、0～1 拍内相位、球坐标、当前拍强调等级、拍点标记和背景偏移。界面数字统一用 1-based。暂停/停止不触发声音或外部业务事件。

输入要求：BPM 为有限正数，演示页范围 30～240；位置为有限非负数。控制方法对无效值抛出说明明确的错误且保留旧状态，页面捕获并展示。外部 source 返回非法快照时组件保留上一有效帧，不让 SVG 产生 NaN；开发环境报告一次诊断。

## 5. 时间与状态逻辑

设连续位置为 q，小节拍数为 N：

```text
absoluteBeat = floor(q)
beatIndex    = absoluteBeat mod N
phase        = q - absoluteBeat
barIndex     = floor(q / N)
```

在整数位置精确落到对应拍点；最后一拍结束后连续到达下一小节第一拍。所有模式共用这一时间帧。

独立时钟保存锚点位置 q₀、锚点时间 t₀ 和 bpm，以毫秒时间计算：`q(t) = q₀ + (t - t₀) × bpm / 60000`。使用 performance.now 的单调时间，不用 Date.now、setInterval 累加或逐帧固定步长推进。

- 开始：从当前位置继续；初始位置是 0。可选一小节预备运动只放在调试页，位置另行显示，不把负值混入正式位置契约。
- 暂停：先采样当前精确位置，再冻结；暂停态仍可手动 seek。
- 停止：复位 q=0，清空尾迹与强调效果，显示第一拍静态位置。
- 变速：用旧速度采样当前 q，再建立新速度锚点，保持位置与相位连续。
- 切换拍号：调试页暂停并复位；组件本身按最新 meter 计算，不擅自控制 source。
- 切换模式、镜像、尺寸：保留当前 q，只重新计算几何。
- seek、循环：更新 revision，立即采样目标位置并清空旧尾迹，不沿旧位置补间飞过去。
- 后台恢复：独立时钟默认继续计时，回到前台直接读取当前 q；外部模式完全跟随 source 的实际策略。均不补播遗漏拍动画。

RAF 仅负责请求绘制。正在播放时持续读取 source；暂停/停止后取消 RAF，用订阅响应参数和位置变化。卸载取消 RAF 与订阅；StrictMode 下不得产生重复循环。只有整数拍、状态等低频信息进入 React 状态；每帧坐标通过 ref 更新 SVG 属性，避免整页逐帧重渲染。

## 6. 指挥模式动画：具体几何与拍点

统一 SVG `viewBox="0 0 240 180"`，坐标从左上角开始。下列是首版候选拍点，表示每拍到达的位置，而非手势所有途经点。

| 图式 | P1 | P2 | P3 | P4 |
| --- | --- | --- | --- | --- |
| 二拍 | (120, 138) | (120, 50) | — | — |
| 三拍 | (104, 138) | (188, 112) | (120, 42) | — |
| 四拍 | (120, 138) | (52, 112) | (188, 112) | (120, 42) |

默认按学习者自己挥右手的视角，向内是向左，向外是向右。镜像使用 `x'=240-x`；数字文字位置镜像，字形不翻转。

phase=0 在当前拍点 Pi，phase=1 到下一拍点 Pj；不是 phase=1 才显示当前拍。每段恰好占一拍；段长不同则空间速度不同，不按全路径总长度匀速。

每段用“弹起 + 移向下一击点”两条三次贝塞尔曲线，而不是直线连多边形。先采用统一可复现的控制点生成规则：

```text
P = 当前拍点，Q = 下一拍点，d = Q.x - P.x
R = ((P.x+Q.x)/2, min(P.y,Q.y)-24)    # 抬手过渡点
曲线 A：P → P+(0,-18) → R-(0.15d,0) → R
曲线 B：R → R+(0.15d,0) → Q+(0,-18) → Q

phase < 0.35：采样 A，u=phase/0.35
否则：       采样 B，u=(phase-0.35)/0.65
```

这里每条曲线依次列出起点、两个控制点、终点；采样公式为 `B(u)=(1-u)³P0+3(1-u)²uP1+3(1-u)u²P2+u³P3`。二拍上下同轴时在抬手顶点短暂低速合理，不做停留。指挥轨迹拍点处故意保留方向突变，形成“击下—反弹”的弹性感。

这是一套初始可调曲线：几何检查通过后，还需通过低速演示确认各拍方向清楚；若四拍跨越或二拍回程难辨，就在 patterns.ts 对对应段覆盖控制点，时间与采样契约不变。

强调等级采用教学提示：二拍 `[强, 弱]`、三拍 `[强, 弱, 弱]`、四拍 `[强, 弱, 次强, 弱]`。通过拍点光环、数字粗细及球颜色区分，不更改拍间时长，也不把教学强弱等同于乐曲每拍的实际音量。

拍点强调只在正在播放且 `phase × 60000/bpm < min(100ms, 0.2×拍时长)` 时出现，由位置直接计算，避免独立 timeout 漂移。轨迹用浅色常驻，运动尾迹默认关闭；调试尾迹按当前时间之前固定采样窗生成，不能按“最近多少帧”决定长度。

## 7. 均拍 / 跑酷模式动画

默认球水平位置固定，背景向左移动；世界坐标中球随时间向前。每个整数拍到达地面，两个拍点之间完成一次上升与下落：

```text
ballX = 84
groundY = 138
H = 64
ballY = groundY - 4 × H × phase × (1-phase)
```

phase=0/1 触地，phase=0.5 到最高点。轨迹为弹跳弧线，保留用户 V 字设想的“下击与回弹”特征；首版采用曲线，避免尖直线在慢速下显得僵硬。一个完整弹跳周期是一拍，不能把下落和上升各计成一拍。

相邻拍点间距 S=72。第 k 个整数拍标记显示于 `x=84+(k-q)×S`；只绘制可见范围及左右各一个预留标记，不能随播放时间增加 DOM 数量。拍号只决定数字和分组：数字为 `(k mod N)+1`，每个第 1 拍用小节线或不同标记强调。

背景移动必须由同一个 q 计算，保证小球触地时当前拍标记正好经过 ballX。切换 BPM 后标记间距不变，移动速度随 BPM 改变。关闭 scrolling 后隐藏跑道，用固定落点与独立拍序指示条表达分组，避免静止跑道与球相位失配。

## 8. 展示调试页

入口：Web HashRouter 新增懒加载路由 `/#/lab/beat-visualizer`。支持开发和生产静态部署访问；入口放帮助页的“实验室”链接，不占播放栏空间。页面自身采用现有 Tailwind 风格，包内 SVG 不依赖宿主样式。

桌面布局：控制区 + 大预览区 + 可展开诊断区；移动端改为纵向。页面内容：

1. 预设：2/4、3/4、4/4；BPM 滑杆和数字输入。
2. 播放、暂停、停止；上一拍/下一拍；位置滑杆（0～2 小节）；拍内相位细调。手动步进先暂停。
3. 模式：弹跳、指挥、并排对比。并排预览共用同一个 source，不能各自创建时钟。
4. 显示选项：镜像、轨迹、拍号数字、跑道滚动、减少动态效果。
5. 时间源：本地时钟 / 模拟外部时钟；后者提供跳转、循环和变速，用以验证接入契约。播放中的位置以 source 为准。
6. 诊断：连续位置、小节、拍序、相位、球坐标、revision、帧间隔；诊断读数最多每秒刷新 10 次，不拖慢动画。
7. 辅助图层：拍点、控制点、路径箭头、击拍基准线；只在调试页开启，组件默认关闭。
8. 可复制配置 JSON（拍号、BPM、模式、镜像等），不序列化运行时对象。预览区显示当前模式及非交互说明。

减少动态效果时：保留拍序变化与静态球位置，关闭连续位移、尾迹、缩放和背景滚动；使用数字与边框提示当前拍。状态可供读屏读取，不把每帧变化写入 aria-live；所有控制有标签并支持键盘。

## 9. 将来与 hh-jianpu 播放器接入

当前 BeatTransport 的 beat 单位为四分音符，Player 内部会减去 playbackDelayBeats；现有 Player 对外主要提供逐拍回调，且回调位于节拍声音启用分支。仅订阅该回调既缺乏连续相位，也会把可视化错误地绑定声音开关。

将来接入时，应用层适配器提供 BeatSource：

- 读取与实际音频呈现对齐的连续位置，明确是当前可闻位置还是调度位置；测量必要的输出延迟，不能直接把提前调度回调当作此刻拍点。
- 正确去除播放前延迟，单独表达预备拍；补充暂停、跳转、循环和状态订阅。
- 声音开关与视觉开关独立；不让新组件覆盖 Player 的单一 onBeat 回调。
- 处理选段起点的拍序原点、弱起与反复，不能一律把任意选段起点解释为小节第一拍。

这部分先保留适配契约，真实接入另做专项验收，不在调试页通过读取 Player 私有 runtime 绕过边界。

## 10. 实施步骤与验收

### A. 包骨架与纯计算

完成 exports、构建、依赖边界、帧计算和时钟。验证 0、1、N 的拍序，小节边界，小数位置；验证变速不跳位置、暂停不推进、恢复连续、seek/revision、无效输入和长时间采样无累加漂移。
