# v0.8.0 计划：独立 H5 小工具与共享简谱核心

日期：2026-10-28  
状态：已进入实施；进度与验收结果见 [v0.8.0-progress.md](v0.8.0-progress.md)  
前置版本：v0.7.6

## 1. 目标

1. 在 `apps/minitool/` 制作独立的小红书离线 H5 小工具，围绕「选择内置曲谱 → 显示谱面 → 播放练习」完成闭环；首版不开放编辑功能。
2. Web 与 H5 共用简谱语义、布局、播放规则及内置曲谱资源模块，应用间没有代码依赖；平台音频、存储和页面交互通过各自适配器实现。
3. 建立独立构建、静态校验和 ZIP 打包流程，交付根目录含 `index.html`、符合小红书容器约束的静态包。

本文件记录已确认的实施范围；实际进展见 progress。版本发布、提交与正式发布按用户后续发布指令执行。

## 2. 已核查的现状与规范

### 项目现状

- `packages/core` 已包含 Parser、AST、移调、布局计算与纯函数 Scheduler，能够处理现有双声部、歌词、反复和奏法。
- Scheduler 已提供起止拍点、实际发声拍数、原谱索引和反复出现次序，是两端共享播放语义的基础。
- 当前 `core/player/synth.ts` 的 `Player` 直接使用 Tone.js Transport、Draw 和 Synth；音色工厂类型也暴露 Tone 类型。仅让 H5 导入当前 core 根入口，不能保证构建结果避开 Tone 及其平台能力。
- 谱面 SVG 组件、曲谱资源与持久化逻辑目前主要位于 `apps/web`，H5 不能直接导入这些应用内模块。
- 现有 `apps/web/dist` 使用模块脚本、根路径资源、外部字体和统计脚本，且携带音频等额外文件，不能直接充当小工具 ZIP。

### 本版采用的规范

- 随包 Skill：[minitool-zip-builder 1.8.0](../.codex/skills/minitool-zip-builder/SKILL.md)。
- 在线契约：[小红书小工具容器能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)，本次已核验，页面标注更新于 2026-10-19。
- 本地核验副本：[2026-10-28 在线规范快照](../.codex/skills/minitool-zip-builder/references/online-doc-snapshot-2026-10-28.md)。开始实施及最终交付前再次获取在线契约，记录变化。

交付约束包括 Chrome/WebView 61、ES2017、包内经典脚本、相对资源路径、单 HTML 入口、离线运行、禁止 Worker/动态执行代码等。ZIP 必须不超过 10 MiB，目标不超过 2 MiB；脚本体积审计通过仅代表体积检查通过。

规范的媒体说明涉及本地音视频，但 ZIP 文件类型白名单未列出 MP3/WAV。本版按严格交集交付，默认使用实时合成音，不携带钢琴采样，不通过改后缀或大 Base64 绕过白名单。原生 Web Audio 在容器中的可用性、解锁和调度表现必须先做验证，不能由普通浏览器播放成功推定。

## 3. H5 首版功能范围

| 功能 | v0.8.0 范围 |
| --- | --- |
| 曲谱入口 | 从共享内置资源目录浏览分类、选择曲谱；仅播放包内资源，不提供源码输入、编辑或自定义曲谱导入 |
| 谱面 | 使用共享布局和 SVG 绘制组件，保留当前语法的单/双声部、多段歌词、Beam、Slur、装饰音及反复显示 |
| 播放 | 播放、暂停/恢复、停止、自然结束、当前音符高亮 |
| 练习 | BPM 调整、节拍器、预备拍、小节 A/B 循环、双声部分别静音 |
| 曲谱切换 | 按稳定分类/曲谱 ID 加载共享内置资源；切谱时停止播放、清理旧高亮与选段，加载失败时给出提示 |
| 音色 | 一种轻量合成音；持续音保持到规定结束拍点，沿用现有奏法规则 |
| 本地恢复 | 记住上次选择的内置曲谱 ID 与练习偏好；不保存曲谱源码副本，保存失败时仍可继续本次播放 |
| 帮助 | 页面内播放、变速、选段、声部与谱面符号说明，覆盖首版交互 |

源码编辑、个人曲谱管理、目录同步、文件导入/导出、剪贴板按钮、图片 OCR、外部 AI 请求、外链、钢琴采样、账号与发布笔记不进入首版。Web 继续提供自己的编辑与个人曲谱流程；H5 首版只提供共享内置资源的播放入口。后续扩展需单独按在线契约设计。

共享曲谱源码继续由同一个 Parser 解释，不建立 H5 专用语法或静默裁剪双声部/装饰音等语义。内置资源在构建期完成解析与完整性校验，运行时保留异常提示。移调计算继续保留在 core，首版 H5 不提供移调后保存或修改资源的入口。

禁止：共享包 → 应用；web ↔ minitool；core → score-view/score-library

### Core 边界

- Parser、AST、Renderer、移调和 Scheduler 保持平台无关，不引用 DOM、React、Tone、`window.xhs` 或任何应用目录。
- 将播放中的音乐规则从 Tone 实现拆出：反复遍次、选段优先级、暂停位置、变速、活动发声、节拍与高亮索引均由共享状态与纯函数决定。
- 状态转换接收明确的时间/拍点和操作，输出新状态及发声、释放、高亮等命令；具体计时、节点创建和副作用由适配器执行。避免在两个应用中各自维护一套 Player 音乐逻辑。
- 共享音源契约保留 `noteOn` / `noteOff`、唯一发声 ID、声部隔离和 `resumed` 等语义，移除 Tone 类型。实际音频节点和输出连接不进入公共领域类型。
- 以拍点为音乐时间的权威值；现有秒数派生字段若继续保留，必须说明用途，不能让变速逻辑依赖起播时的固定秒数。
- Core 的运行时依赖中移除 Tone；Tone 由 Web 应用声明并在用户播放时按需加载。H5 的完整依赖闭包必须不含 Tone。

### Web 迁移与公共 API

- 把现有 Tone 传输、合成音、采样和混音实现迁入 Web 音频适配器，接收共享播放命令。
- Web 的钢琴/合成音注册、资源路径与偏好继续由 Web 组合；全局 Transport 的取消和释放由实例明确拥有，避免跨实例干扰。
- Web 页面可通过应用内门面维持现有调用形态；门面只转发状态和命令，不复制 Scheduler 或奏法规则。
- 当前 core 根入口导出的 `Player`、`createSampleInstrument` 及 Tone 相关工厂需要迁移。实施时列出调用点，提供新的平台无关入口和 Web 内替代导入，更新 API 文档；将导入/构造变化作为 v0.8.0 的兼容性变更记录，不能以隐藏反向导入维持旧入口。

### 共享谱面与 H5 页面

- 从 Web 提取 `ScoreView`、小节/音符绘制及连线计算到 `@hh-jianpu/score-view`；其输入是 core 的布局、播放高亮与受控回调。
- 共享组件不读取 Web Zustand store、不导航、不访问持久化或平台音频，不导入 Web 配置/样式；通用样式随包显式提供，应用负责页面外壳。
- H5 使用 React 18、TypeScript、Vite 与轻量 CSS，独立维护页面状态；共享包的 React 使用 peer dependency，避免重复打包。
- 包间只通过声明的 workspace 依赖和公共 exports 引用，不用 alias 指向另一应用，也不通过相对路径穿透包内源码。

### 共享内置资源模块

- 新建 `@hh-jianpu/score-library`，将 `apps/web/resources/scores/` 的分类配置与曲谱整体迁入 `packages/score-library/resources/scores/`，作为唯一维护目录；两端不复制或分别维护曲谱源码。
- 同时抽取 Web 的 `ScoreTemplate`、`ScoreCategory`、JSONC 读取校验、排序、默认曲谱与 ID 查询逻辑，提供平台无关的公共接口。保留现有稳定分类 ID、曲谱 ID、源码、来源说明和 `enabled` 语义，避免 Web 默认曲谱与加载行为变化。
- 资源包不依赖 React、Zustand、DOM、Tone、小红书 API 或应用目录，也不承担播放、个人曲谱保存和页面导航。其数据读取不依赖 core；音乐语义校验在构建/测试流程中组合资源包与 core 完成，core 不反向依赖资源。
- 资源发现与 JSONC 转换在资源包构建期完成，输出可供两端导入的静态 ESM 数据与类型；应用消费公共 exports，不要求两端各自扫描源码目录，也不在运行时 `fetch` 资源。
- 首版默认向两端提供同一组已启用分类和曲谱；新增或修改一首曲谱后，两端重新构建即可获得同一内容。将来如包体确需筛选，按稳定 ID 在构建期生成清单，仍使用同一资源源文件，并在摘要中列出纳入范围。
- H5 发布包只带构建转换后的允许类型，不直接携带 `.jsonc`、构建清单源文件或 Web public 音频资源；核对解压后文本体积，避免共享目录增长后无条件装入过大数据集。
- 曲谱资源保持只读。Web 打开模板后的个人副本沿用原有隔离保存规则；H5 只记录资源 ID 与偏好。资源下架或 ID 失效时回退到有效默认曲谱/首个有效曲谱，空资源集显示明确状态，禁止自动播放。

## 5. H5 音频与容器适配

### 首先验证音频可行性

P0 制作可丢弃的最小实验：经典脚本、用户点击激活 AudioContext、三角波短音/持续音、停止与再次播放。打包后由创服平台模拟器、Android 和 iOS 验证。实验包与正式应用分开，不能把实验验证页装入正式 ZIP。

静态可行性成立后可继续其余开发；未获取容器实测结果时明确保留风险。若容器禁止关键 Web Audio 能力，先核对在线公开替代能力；没有可用方案时记录播放功能的具体阻塞，不交付白屏或无声却标为验收通过的工具。

### 时钟、发声和生命周期

- 使用 `AudioContext.currentTime` 作为音频时间，主线程定时器只负责提前调度，禁止 Worker、AudioWorklet 和 Blob 脚本。
- 初始前瞻窗口建议 100 ms、唤醒间隔建议 25 ms，作为待测参数；定时器和 `requestAnimationFrame` 不作为音乐时间源。
- 音频事件携带播放代次、声部及独立发声 ID；停止、切谱、变速和循环边界能取消尚未生效的旧命令并释放相关节点。
- 中途变速时锚定当前拍点，撤销并重排未发生事件，修正活动长音的结束时间；不得产生同一音重复起音或旧速度下的提前结束。
- 暂停记录音乐拍点并释放声音；恢复只重建仍处于发声门限内的持续音。循环与反复入口、节拍器和预备拍共用共享状态规则。
- UI 高亮读取同一播放状态，通过 rAF 绘制，不能反过来驱动声音。页面隐藏、容器退出或音频上下文中断时停止/暂停并清理；恢复可见后由用户主动恢复，避免后台补播。
- 首次播放检测并解锁音频；不支持、权限/激活失败或上下文恢复失败时给出可理解状态和重试动作。

### 存储与窗口

- 客户端 9.46+ 且存在公开 Storage API 时优先使用；同步启动信息缺失时异步获取，方法存在仍需处理调用失败。
- 低版本或未注入环境才回退到带异常处理的浏览器存储。记录存储来源/版本与更新时间，迁移后使用明确的读取优先级，避免旧偏好覆盖新设置。
- 仅持久化上次曲谱的分类/曲谱 ID、BPM、节拍器、预备拍和声部偏好等少量状态，不存源码、AST、资源副本或个人草稿。曲目专属设置按曲谱 ID 隔离，切谱不误用上一曲的选段；偏好恢复不自动开始播放。
- 设置在内存立即生效；持久化异步串行、防抖、带代次，防止旧请求晚到覆盖新内容。单 key 保持在 1 MiB 内，总存储遵守 10 MiB 配额。
- 9.49+ 的窗口信息能力在满足条件时优先用于按钮避让与安全区；缺失时采用 CSS/视口回退。所有桥接调用集中到适配层。
- 安全区同时支持容器变量与 `env()`，并保留普通 padding 基线；`visualViewport` 等高级 API 使用前检测。

## 6. 独立构建、校验与打包

- 新增 `dev:minitool`、`build:minitool`、`audit:minitool`、`package:minitool`，不复用 Web 的 dist 或复制其整套 public 资源。两端构建前先生成共享资源包及共享组件产物，开发模式监听资源更新，避免读到旧资源构建。
- 最终脚本构建为单一 IIFE 经典脚本；必要依赖在构建期合并，不保留 `import`、`export`、动态 import、`type="module"` 或 modulepreload 网络逻辑。
- 明确设置 JS/CSS 的 Chrome 61 目标；检查运行时 API 并按实际使用提供局部兼容。CSS 以普通 Flex/margin 等为基线，现代特性按需增强；不能将转译语法误当作 Web API/CSS 兼容保证。
- `index.html` 包含语言、字符集、viewport 与 `viewport-fit=cover`；所有引用相对路径，脚本外置，不自建 CSP，不含在线字体/分析脚本。
- 产物只保留规范白名单类型，根目录唯一 `index.html`；禁止 sourcemap、配置、开发目录、音频文件和其他无关材料进入 ZIP。
- 将输入目录构建到 `apps/minitool/dist/`，ZIP 输出到 `artifacts/hh-jianpu-minitool-v0.8.0.zip`，摘要输出到同级独立 Markdown；报告和规范副本不装入上传包。
- 目录和最终 ZIP 都执行随包体积审计；自有审计补充文件类型、根入口、路径解析与资源存在性、ES2017/经典脚本、禁用能力、外部资源和 Base64 检查。
- 语义扫描区分实际调用与无害字符串，人工复核依赖内部代码；不能靠改变量名或扫描忽略掩盖禁用能力。先审计再打包，最后从 ZIP 清单及解压内容复核同一产物。
- ZIP ≤10 MiB，目标 ≤2 MiB；单条 Base64 解码后 ≤1 MiB。超出文本建议值时记录解析成本审查，不依靠压缩率隐藏大数据。

## 7. 架构与行为验收

### 自动门禁

- 依赖规则覆盖静态导入、动态导入、re-export、类型导入、配置 alias 和包 exports：禁止 core/score-view/score-library 依赖应用，禁止 web 与 minitool 互相引用，禁止 core 反向依赖 UI 或资源包。
- 资源校验覆盖分类配置、重复 ID、排序、启用状态、来源说明、空资源集和资源缺失；所有启用曲谱通过 core 解析及播放所需语义校验。核对 Web/H5 的分类与曲谱清单一致，同一 ID 的源码一致，新增/修改资源只需编辑一个源文件。
- 检查 H5 构建依赖清单，确保没有 Tone、Web store、OCR、文件目录服务及其禁用能力残留；core 声明文件不泄漏 Tone/React/小红书类型。
- 同一套音乐 fixture 验证共享播放状态与两端适配契约：起止拍点、事件次序、唯一 ID、反复遍次、选段裁剪、暂停恢复、变速与声部静音结果一致。
- Core 覆盖原有语法、序列化和布局回归；共享 SVG 组件覆盖高亮索引、双声部对齐和多段歌词；不为 H5 另写一套解析/调度断言来源。
- Web 原有质量门禁继续通过：`pnpm lint`、`pnpm build:core`、`pnpm test`、`pnpm build:web`；新增共享资源/组件构建、H5 构建、依赖边界检查和产物审计纳入 CI。
- H5 页面只暴露内置曲谱选择和播放练习；不出现编辑器、源码输入、个人曲谱保存及导入入口。覆盖资源 ID 恢复、失效回退、空分类/空列表、切谱清理和偏好写入失败。

### 音乐与音频验收

| 场景 | 通过标准 |
| --- | --- |
| 普通音、休止、断音、长音 | 起止拍数与现有 Scheduler 一致；持续音中后段可闻，释放后无常驻音 |
| 同音 Slur、延长线中途选段 | 连续部分不重复起音；选段入口恢复有效持续音，出口正确释放 |
| 反复与 A/B 循环 | 高亮回到原谱；边界无跨轮常驻音、重复起音或漏掉停止事件 |
| 四拍长音中途减半 BPM | 原有语义样例约从 2 秒延长到 3.5 秒；以实际变速拍点核对，不仅检查总时长 |
| 暂停、继续、停止、切谱 | 保留/重置规则明确；异步旧任务不能重新发声或覆盖状态 |
| 双声部与静音 | 同拍同步起音，唯一 ID 隔离；释放或静音一部不误伤另一部 |
| 预备拍与节拍器 | 等待完整预备拍时长，首次起音和节拍对齐，循环不重复预备拍 |

自动音频渲染与事件日志用于验证时间和持续性，实际试听用于确认无明显爆音、卡顿及不可闻长音。不能只通过 UI 高亮或测试数量宣称播放合格。

### 容器与真机验收

- 创服平台模拟器验证完整流程；同一 ZIP 分别在 Android、iOS 扫码验证，记录包哈希、客户端版本、设备、声音与布局结果。
- 覆盖窄屏、横竖屏、资源分类/曲谱选择、长谱滚动、弹层、安全区和顶部原生按钮避让；关键操作不依赖 hover，首版不依赖源码编辑或软键盘输入。
- 验证音频首次解锁、暂停恢复、中途变速、循环、后台/前台切换和中断后的状态；确认无外部请求、存储失败可恢复。
- 无 Chrome 61 运行环境时，明确记录 JS/CSS 兼容性未实测；无设备性能数据时标注性能未实测。
- 平台模拟器与 Android/iOS 验证由用户执行或另行明确授权；待验证项不阻塞静态 ZIP 交付，但不得据此宣称平台或真机验收通过。
