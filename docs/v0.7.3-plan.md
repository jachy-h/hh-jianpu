# v0.7.3 计划：竹笛入门入口与反复记号

补充计划（2026-10-27）：[断音／顿音调研与开发计划](plans/v0.7.3-staccato-research-and-plan.md)。该补充尚未实施，包含实心倒三角的音乐语义、播放比例建议与验收标准。

日期：2026-10-26
状态：计划已整理，尚未实施。以下反复边界和交互规则为本版建议方案。

## 1. 目标与现状

1. 增加「竹笛入门」入口，沿用「示例曲谱」加载后进入编辑和播放页面的流程；具体曲谱由用户后续补充。
2. 支持前反复记号 `||:` 和后反复记号 `:||`，打通输入、渲染、播放、移调与保存。

现状核查：

- 首页示例调用 `loadExample(key)` 后跳转 `/edit`，可复用这一交互。
- `setSourceImmediate()` 会写恢复草稿，不能在仍绑定个人曲谱 ID 时直接加载公共曲谱。
- Tokenizer 仅识别单个 `|`，AST 和播放调度没有反复结构。
- 实际执行 `parse('||: 1 2 3 4 | 5 6 7 1 :||')`，得到两个「未识别的字符: 冒号」错误；不存在反复支持。

## 2. 竹笛入门

### 展示和加载

- 首页增加与「示例曲谱」并列的「竹笛入门」入口/分区；曲目按钮沿用示例的展示方式。
- 曲目点击后加载其源码并进入现有 `/edit` 页面，可编辑、播放、变速、选段和移调。
- 首版曲目列表允许为空，展示「竹笛入门曲谱待补充」，不添加虚构教材曲目或不可点击的占位曲目。
- 独立维护竹笛资源列表，每项包含稳定 `id`、展示名称 `name` 和简谱 `source`；可选来源说明。提供新增曲目的简短说明，后续补曲不需修改页面逻辑。
- 无需新增独立课程页、播放器、账号、收藏或进度系统。

### 保存隔离

- 抽取示例和竹笛曲谱共用的模板加载动作，保留已有示例 API。
- 加载前完成旧稿待保存任务；保存失败时留在当前页面，保留旧稿并反馈错误。
- 加载成功前停止播放和倒计时、清空旧选段、解除 `currentScoreId`，再加载模板源码。
- 返回明确加载结果，只有成功后才导航，避免保存失败仍切换页面。
- 单纯打开曲目不创建个人曲谱；首次编辑时依现有示例行为创建个人副本，不能覆盖原个人曲谱或内置资源。

验收：空列表显示正常；用测试曲目验证加载、编辑、刷新恢复和移调；编辑个人曲谱 A 后快速加载竹笛曲谱，A 不丢失、不串写；模拟保存失败时不切换。

## 3. 反复记号语义

### 本版支持

- `||:`：放在小节起点，标记反复段开始。
- `:||`：放在小节终点，标记反复段结束；该段总共演奏两遍，再继续后续小节。
- 只有后反复时，从曲首重复一次；有前反复却没有后反复时报明确错误。
- 支持单小节反复、多个顺序排列且不嵌套的反复段，以及同一边界结束上一段再开始下一段（`:|| ||:`）。
- 不产生额外空小节，不改变记谱小节编号，不把重复的谱面复制出来。
- 不支持嵌套反复、房子/跳房子、指定反复次数、D.C./D.S.；不支持的反复结构须报错，不能静默播放为普通小节线。
- 前反复出现在未结束的小节中、空反复段等非法位置需包含源码位置诊断。
- 既有 `|` 和 `||` 的行为保持兼容，不把普通双竖线解释为反复。

示例（每小节 4 拍）：

```text
||: 1 2 3 4 | 5 6 7 1' :|| 1' - - - |
```

预期播放小节顺序：`1 → 2 → 1 → 2 → 3`。在 BPM 120 时，音乐时间为 10 秒（不含预备拍和音源释放尾音）。

### 与已有能力的关系

- 全曲播放遵循谱面反复，播放高亮回到原谱对应的小节和音符。
- 完整 A/B 练习选段优先：按书写顺序播放所选小节并循环，暂不展开其内部谱面反复；界面和帮助明确此规则。清除选段后恢复谱面反复。
- 暂停/恢复保留所在遍次和实际播放位置；变速不重置遍次；停止后重新开始从第一遍起播。
- 双声部使用共同的反复顺序：本版要求两声部对应边界的记号一致，不一致则诊断并阻止播放。
- 反复跳转入口重新建立发声状态，不能把上一遍的持续音错误续接到下一遍；预备拍只在首次开始时执行。

## 4. 实现路径

### Parser / AST / 序列化

- Tokenizer 优先按最长匹配识别完整 `||:` 和 `:||`，再处理普通小节线。
- 在小节结构上增加可选的反复起止信息，保留源码范围；旧谱缺省无反复，无需迁移。
- Parser 处理边界归属、配对和双声部一致性校验，避免以普通 BARLINE 丢弃语义。
- `scoreToSource`、移调保留反复记号；源码保存和 JSON 备份往返不丢失。
- 编辑器高亮识别反复符号，补全在线帮助及语法指南。

### Renderer

- Layout 计算反复线及圆点占位；ScoreView / MeasureView 绘制对应起止符号。
- 检查行首、行末、跨行、相邻反复段和双声部联谱，避免与音符、升降号、歌词重叠。

### Player

- 用纯函数从记谱小节生成有限播放顺序，再进行音符调度；保持原始 AST 和谱面布局不变。
- 区分原谱音符索引与播放出现次序：同一音符重复播放时保持原索引用于高亮，使用独立的播放时间位置。
- 双声部共用播放顺序，不能各自独立跳转。
- 调整节拍回调、结束时间、暂停恢复及选段逻辑；不能仅在原事件上按小节编号筛选，否则会把展开后的重复事件误带入 A/B 选段。
- 检查重复入口的延音、休止、装饰音和跨界连线；无效结构不得导致无限调度。

## 5. 验证和交付

- Core：起止符号分词、源码定位、边界与非法结构、隐式曲首、多段/单小节反复、双声部一致性、序列化及移调往返。
- 调度：上述示例顺序和总拍数、原谱高亮索引、重复入口持续音、休止、A/B 优先行为、双声部同步。
- Web：模板加载保存隔离、失败不导航、空列表、反复错误反馈、播放状态与高亮。
- 浏览器：桌面与手机宽度排版；试听反复跳转、变速、暂停恢复、切谱停止和选段循环。
- 门禁：`pnpm lint`、`pnpm build:core`、`pnpm test`、`pnpm build:web`。
- 更新在线帮助、`docs/user-guide/notation-syntax.md` 和版本变更说明；所有新增语法示例必须可解析并与实际播放一致。

建议实施顺序：竹笛入口与安全模板加载 → 反复解析/序列化 → 谱面渲染 → 播放调度与交互 → 回归和文档。

本计划不执行版本发布或提交；版本号更新和发布在用户要求发布时处理。
