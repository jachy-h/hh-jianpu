# v0.8.3 计划：分享到评论并恢复曲谱页面

日期：2026-10-30
状态：规划，待实施

## 目标

1. 在小工具播放页的「横向阅读」按钮旁增加「分享到评论」，由用户点击进入评论分享流程。
2. 用户从该评论重新打开小工具时，自动进入分享的曲谱播放页，等待用户主动播放。

## 平台能力与待确认事项

[小红书小工具文档 §3.9](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3) 提供 `interactionOpenApi`：以 `payload.action: 'post_comment'` 打开评论编辑器，并通过 `payload.miniToolSnapshotInfo` 携带最大 2KB 的 JSON 字符串。客户端须为 9.49 及以上，调用须由用户主动触发；调用时容器会关闭小工具并打开评论区。有效快照可在从评论区重新打开小工具时读取，恢复逻辑由开发者实现。

**实施前置验证**：公开文档未说明重新打开时快照所在的具体字段或返回形态。先向平台确认或在模拟器与真机上验证启动参数及重新进入场景，记录实际契约；不要猜测字段，也不要把普通分享按钮视为已支持携带快照。若契约无法确认，保留恢复功能待验证，不能宣称端到端完成。

## 分享流程

- 在 `apps/minitool/src/App.tsx` 的播放页顶栏，将「分享到评论」放在方向切换按钮旁；兼顾窄屏、长曲名及横向阅读，按钮保持可见且可点击。
- 分享当前内置曲谱的稳定标识，使用带版本的精简快照，例如 `{"version":1,"page":"score","scoreKey":"分类ID/曲谱ID"}`；不携带源码、播放进度或个人数据。检查序列化后的大小不超过平台限制。
- 容器适配层增加类型化的评论接口封装，复用客户端版本判断，并检查 API 是否存在；客户端不支持或普通浏览器中给出明确提示。防止重复点击，处理取消、失败及超时，恢复按钮状态。
- `payload` 使用 `action: 'post_comment'` 和简短评论文案；不要求生成图片，显式设置 `saveToAlbum: false`。调用成功仅表示路由成功，实际发布由用户在评论编辑器中决定。分享前停止播放及预备拍，避免离开时音频继续运行。

## 恢复播放页

- 按验证后的平台契约读取快照，处理冷启动及容器复用时重新进入的实际生命周期；避免异步结果覆盖用户已经主动选择的曲谱。
- 对输入做大小、JSON、版本、页面类型和曲谱 ID 白名单校验，以现有 `SCORE_CATEGORIES` 查找曲谱。有效时复用选曲逻辑初始化默认练习设置，进入对应播放页，但不自动发声。
- 缺失、格式错误、超限、未知版本或曲谱已下架时保持列表页可用，必要时提示曲谱不可用；不因无效分享阻塞启动。返回列表仍按现有逻辑停止播放。
- 分享只承诺恢复内置曲谱页面；设备本地存储不能作为跨用户传递数据的依据。

## 实施与验收

1. 确认快照接收字段、冷启动和复用场景，记录平台版本及证据；据此设计容器适配接口。
2. 实现分享按钮、平台调用与异常提示，以及快照校验和页面恢复；更新小工具说明。
3. 添加有意义的回归：有效 / 无效 / 已下架快照、异步启动与用户选择竞争、桥接不可用和失败、重复点击；验证分享目标与恢复目标一致，恢复后不自动播放。
4. 运行项目质量门禁及 minitool 构建与审计；在平台模拟器和 Android、iOS 真机分别验证：发布评论、从评论重新进入指定曲谱、取消和失败、低版本降级，以及窄屏和横向布局。记录未验证项，不以浏览器模拟代替端到端验证。

本阶段仅制定计划；版本号、CHANGELOG 和发布在后续流程处理。
