# v0.7.1 规划：上下双声部联谱

状态：S5 基础范围已于 2026-10-26 获准实施；其余语义提案保持候选，进度见 v0.7.1-progress.md
前置版本：v0.7.0 语法一致性基线

## 目标

在 v0.7.0 已明确的语法和测试基线上，评估需要改变既有音乐语义或增加语法的能力。每项提案在排期前需确定用户场景、语法形式、旧谱兼容策略和迁移验收。

## 候选项

### S1. 歌词按旋律块绑定

当前实现会把所有歌词行合并后，从全曲第一个有效音符开始分配。提案是让 `C` 歌词行绑定紧邻的前一旋律行/小节组，避免局部补歌词错位。

待确认：

- 如何表示同一旋律的多段歌词、重复段落及跨行歌词。
- `Q` 行、未标记旋律行、小节线和空行如何确定绑定范围。
- 旧谱是否继续采用全曲顺序分配；是否需要语法版本或显式迁移。
- 歌词缺少/多出音节时的诊断级别；括号组如何处理。

建议语义：休止、延长线、换气和倚音不消费歌词；`_` 表示一个普通发声音符没有歌词，不给休止符占位。

### S2. 显式 Tie（同音延音）

目前 `-` 表示延长时值；圆滑线括号也可能在播放时合并连续同音。提案是区分“书写时值延长”和“同音跨音符持续发声”，让 Tie 与 Slur 的记谱及播放含义明确。

待确认：

- 选择易输入且不与现有 `-`、`~`、括号冲突的标记。
- Tie 是否必须连接音高相同的相邻音符，跨小节和变音记号如何校验。
- 旧圆滑线中的同音合并行为如何兼容，如何避免旧谱发声变化。
- 渲染、播放、移调和序列化的统一验收样例。

### S3. 速度单位与复合拍节拍

当前 BPM 没有显式单位，界面与播放器将速度视作四分音符拍。提案是允许指定速度单位，并在 6/8 等拍号下表示分组节拍。

待确认：

- 字段形式及旧 `速度: N` 的默认单位。
- BPM 是否允许附点音符单位；复合拍的默认分组是否由用户指定。
- 播放器、节拍器、倒计时、练习倍率及导入导出的对应语义。
- 从旧文件迁移后播放时长必须保持不变。

### S4. 弱起小节与不完整小节

当前节拍验证要求每小节与拍号完全相等。提案是显式支持弱起、结尾补足及有意不完整的小节。

待确认：

- 弱起和结尾小节如何声明、两者如何验证合计拍数。
- 中间不完整小节是错误、警告还是允许的自由节奏。
- 无小节线段落及歌词映射的处理方式。

### S5. 上下双行曲谱（双声部联谱）

来源：2026-10-26 用户提出，参考上下两行、左侧大括号联结的简谱图片。此处“上下段”按上下声部同时演奏理解；如果是前后顺序演奏的两个段落，应继续使用普通旋律换行，不引入双声部语义。

#### 场景与展示目标

- 上行为主旋律，下行为伴奏或第二声部；两行共享调号、拍号、速度和小节编号。
- 每组谱表左侧显示大括号与起始线，上下对应的小节线对齐；响应式换行以整组谱表为单位，不能将上、下声部分到不同组。
- 横向位置按小节内的音乐时间对齐。例如上声部两个八分音符对应下声部一个四分音符时，两声部起拍位置相同，下一个共同拍点也须对齐。不能简单堆叠两个现有的独立布局。
- 播放时两个声部同时发声；可用贯穿上下行的播放指示线表示拍点，同时高亮两个声部当前的音符。
- 参考图下声部还有叠置音和竖向波浪线（琶音记号）。双行排版本身不足以完整表达这部分，需单独定义和弦及琶音语义。

#### 建议范围与优先级

2026-10-26 用户要求开始实施。v0.7.1 先落实基础双声部闭环；S1 至 S4 仍需单独定稿。每声部歌词沿其自身时间轴顺序绑定，不改变旧谱歌词语义。

1. **基础范围**：固定两个声部，各声部内为单音序列；共享拍点布局、联谱标记、同步播放、分别试听/静音、按共同小节选段与循环。支持现有休止、延长线、八度、减时线、Beam 和 Slur；分组和延音状态严格隔离到所属声部。
2. **完整参考图范围**：增加同一声部的和弦（同一时刻多个音高）与琶音记号。和弦按一个节奏事件计时，不能把叠置音串成旋律；琶音需明确方向、展开时间及其与下一拍的边界。不将现有波音 `~` 直接解释为琶音。
3. **后续范围**：任意数量声部、每声部独立调号/拍号/速度、交叉声部连线、复杂钢琴踏板与配器。基础双声部不承诺这些能力。

若 v0.7.1 仅纳入基础范围，应明确标注“支持双行单音声部”，不宣称已完整支持参考图中的伴奏记谱。

#### 基础双声部输入语法

采用显式声部标记，不改变现有连续 `Q` 行的顺序含义：

```text
声部: upper=旋律, lower=伴奏

Q[upper] 3/5/ 7/1'/ 1' - | 2/4/ 6/1'/ 2' - |
Q[lower] 1 0 0 1         | 6. 0 0 2          |

Q[upper] 3 5 7 - |
Q[lower] 1 0 0 1 |
```

- 示例按 4/4 拍编写，仅演示双行和拍点对齐，下声部未表达参考图的和弦、琶音。
- 同一声部的后续行追加到该声部时间轴，各声部按全曲小节序号配对；空行仅提高可读性，不作为隐含配对依据。
- 进入显式双声部模式后，无声部标记的旋律或歌词行报错，未知声部报错。
- 每个对应小节分别验证时值；缺少声部小节、超拍、欠拍需给出声部及源码位置，不静默拉伸、补休止或截断。整小节休止用 `0` 写足时值，例如 4/4 拍写 `0 0 0 0 |`。
- 单声部旧谱、`Q` / `P` 别名和裸旋律保持原义；不能把既有两行 `Q` 自动配成双声部。
- 和弦、琶音写法另行评审；歌词使用 `C[upper]` / `C[lower]` 显式归属声部，沿各自声部顺序分配。未定稿的写法不能被导入、移调或保存流程静默丢弃。

#### 实现影响与约束

- **AST / Parser**：当前 `Score.measures[].notes` 只表示单声部；需要增加显式声部结构、稳定声部标识和源码映射。对外 API 的兼容方式与数据格式版本需要先确定，旧谱归入默认声部，不重复存储两份可变旋律数据。
- **Renderer**：当前布局按单行音符槽分配宽度；双声部需合并两行的起拍时间点，结合两行符号、歌词的最小间距计算共享横坐标。行高按上下声部边界框共同计算，预留大括号、低高八度点及歌词空间。
- **Player**：当前调度逐小节、逐音符累加时间；需各声部分别生成事件后，汇入统一拍数时间轴。延音、圆滑线、装饰音状态按声部管理；已有 PolySynth 容纳释放尾音不等于已有多声部调度。
- **高亮与练习**：当前使用单个 `currentNoteIndex`；需能表示同拍的多个活动事件，并保留声部与音符的定位。选段、循环、变速、暂停恢复和跟随滚动共享整谱时间轴；静音不改变时长或另一声部节奏。
- **编辑与存储**：编辑器高亮、诊断定位、点击谱面定位、移调、源码序列化、复制与备份往返保留声部归属及空格 Beam 分组。不能在旧处理链中将双声部降级为顺序单声部。
- **说明与示例**：正式落地时更新 `/help`、`docs/user-guide/notation-syntax.md`，并增加可播放的双声部内置示例。

#### 验收用例

1. 上述示例两声部均为 3 个 4/4 小节；在四分音符 BPM 120 下，主体播放时长为 6 秒，两声部同时起拍，不串联为 12 秒。
2. 上声部八分音符、下声部四分音符的共同拍点与小节线纵向对齐；调整字号、拖动分栏、移动端换行后仍保持成组排版，符号和歌词不重叠。
3. 下声部休止期间，上声部继续；同时发声的不同音高都能听见；静音任一声部不改变另一声部起拍、总时长或节拍器。
4. 上下声部使用相同音高或 Slur 分组时不互相延音；跨小节延音与选段入口按各自声部独立处理。循环多轮、变速、暂停恢复后仍同步。
5. 缺失或不等长小节显示明确的声部与位置诊断；旧单声部示例的解析、排版、播放与移调保持原义。
6. 双声部 `parse → serialize → parse`、移调及备份恢复保留两声部时值、音高、歌词归属和 Beam/Slur 分组。
7. 若纳入和弦与琶音：补充叠置音对齐、和弦同起、琶音展开、拍数不重复累计及循环边界的视觉和试听验收。未纳入时，对相关输入明确报未支持。

## 共通约束

- 不覆盖 v0.7.0 的语法一致性工作；先确认现状、规范示例与回归测试。
- 未经确认的提案保持候选状态，不进入实现。
- 语法演进必须能区分旧谱与新语义；提供迁移预览，不静默改写或破坏用户曲谱。
- 对每项已确认的提案，同步更新 Parser、编辑器高亮、AST、序列化、Renderer/Player、帮助文档及测试。
- 评估跨平台键盘输入可达性，避免与现有符号或编辑操作冲突。

## 排期门槛

每项候选进入 v0.7.1 前需补齐：目标用户与具体场景、语法示例、旧谱兼容/迁移方案、渲染和播放规则、验收用例，以及是否影响 v0.7.0 已承诺行为。
