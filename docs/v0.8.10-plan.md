# v0.8.10 计划：时值排版

日期：2026-10-30
状态：方案已确认，待实施

## 1. 目标与范围

新增可选的「时值排版」，用谱面横向距离表达时间：同样的时值在全谱占用同样的时间宽度，音符起点之间的距离与起音间隔成比例。

保留现有自然排版和小节对齐模式，提供时值排版切换。本版交付布局计算、Web 入口、回归测试及使用说明；匀速播放竖线、谱上节拍球和音符时值进度条后续安排。

## 2. 全谱统一的空间基准

采用已确认的方案：最短音建立初始比例，全谱碰撞检查修正比例，按起始拍数定位，统一比例后换行。

1. 遍历全谱全部声部，找到最短的正时值事件，休止符也参与。装饰音、换气符、小节线等零时值符号不参与最短时值计算。
2. 根据最短事件所需的可见空间与安全间距，计算初始每拍宽度。例如 ¼ 拍需要 24px，则初始每拍宽度为 96px。
3. 检查全谱各声部相邻事件的符号和歌词边界；若初始比例不足以避免碰撞，统一增大全谱每拍宽度。不能仅给局部事件额外加宽。
4. 得到最终每拍宽度后，再计算小节宽度和换行。全谱共享这个比例，不按行或小节重新拉伸。

不能只检查最短音：较长音符也可能带升降号、装饰音或长歌词组，需要更大的空间。实现应将正起音间隔上的避碰约束换算为每拍宽度的下限，取全谱最大值；零间隔附件单独布局，不做除法。

时间单位沿用 core 的统一时值单位（四分音符为 1），避免把不同拍号的分母、速度和视觉宽度混为一谈。改变播放速度不改变谱面布局。空谱或没有正时值事件时使用明确的默认比例。

## 3. 起点定位与符号空间

```text
音符横坐标 = 小节时间起点 + 音符在小节内的起始拍数 × 每拍宽度
```

比例约束作用于音符起点，不能把数字放在各自时值占位框的中央，否则长短音交替时起音距离会失真。长音、附点音、休止符和延长线按实际时值推进时间；连音、装饰等语法沿用现有解析语义。

等宽字符格可用于歌词宽度估算，但不强制所有可见符号等宽。数字及附属符号使用现有边界框；升降号、八度点、减时线按实际方向计算占用空间，不按源码字符数量累加。多段歌词取各段所需空间约束的最大值。

小节线、反复记号、换气符等零时值符号放在对应时间位置附近，其空间纳入附件避让和谱行边界预留。不能通过在时间轴内部插入额外宽度来容纳它们；必要时增大全局比例或调整附件位置。相邻小节的时间起点之差必须等于前一小节实际时长乘以每拍宽度，不能重复累加小节内边距。

双声部共享小节时间轴与每拍宽度，同一时刻的音符横坐标一致；分别检查各声部符号和歌词的碰撞。小节时长沿用现有共同时间轴语义，弱起和不满小节不强行补齐拍号时长。

## 4. 换行与交互

- 优先在小节之间换行，保留现有源码分行偏好的语义；允许行末留白。
- 不为铺满屏幕分别拉伸各行。字号或内容变化后可重新计算全局比例；容器宽度变化主要影响换行。
- 单个小节超出可用宽度时保留完整小节与时间比例，通过现有谱面容器提供横向浏览，不能局部压缩或裁切内容。
- 全谱仅一处密集短音或长歌词也可能使整体变宽，这是统一比例的预期取舍，用户可切回现有排版。
- 排版切换沿用现有设置的交互与保存约定；音符索引、编辑定位、播放高亮及谱面跟随仍绑定相同事件。

## 5. 实施步骤

1. 扩展布局模式配置，在 renderer 内实现纯数据的时间位置、空间约束和全局比例计算，不依赖 Player、Tone.js 或应用状态。
2. 单声部和双声部复用一致的时间比例规则，接入小节分组、歌词及符号布局；不改变 Parser 和播放调度语义。
3. Web 增加「时值排版」选项，检查模式切换和响应式容器。共享消费者继续使用兼容默认值，不新增 minitool 专用入口。
4. 补充测试、帮助中的排版说明及浏览器验收记录。实现时核查其他共享消费者的构建与默认表现。

## 6. 验收标准

- 混合 ¼、½、1、2 拍及附点时值，起音距离严格对应时间差；跨小节仍保持同一比例。
- 最短音不是最复杂音时，升降号、装饰音及长歌词仍不碰撞；多段歌词和双声部约束都参与全局比例计算。
- 休止、延长线、连音、零时值附件、弱起、空谱和单小节过宽都有明确结果，无无穷值或无效坐标。
- 不同谱行每拍像素宽度一致，末行不拉伸；改变 BPM 不影响坐标，改变容器宽度不破坏时间比例。
- 现有自然排版、小节对齐及旧设置保持兼容，编辑定位、音符高亮、反复播放和双声部跟随正常。
- 浏览器检查桌面与移动端、不同字号、多段歌词、长谱和横向浏览，实际确认符号与歌词无重叠或裁切。
- 实施后运行 `pnpm lint`、`pnpm build:core`、`pnpm test`、`pnpm build:web`，并核查共享消费者需要的构建检查。
