# v0.7.0 规划：可靠编辑与练习体验

状态：实现与自动化门禁完成，待人工环境验收（详见 v0.7.0-progress.md）
确认日期：2026-10-26
基线版本：v0.6.2

## 1. 版本目标

围绕“可靠保存、准确移调、顺畅练习”完善现有产品。保留文本编辑、实时预览、曲谱管理以及 Parser → AST → Layout / 播放调度的核心架构。

用户应能放心编辑和切换曲谱，辨别保存及备份结果，准确移调，并通过选段循环完成练习。

## 2. 检查基线

- 核心库测试：12 个测试文件通过，191 项通过、4 项跳过。
- `pnpm build`：通过；存在超过 500 kB 的构建 chunk 提示，需区分首屏与懒加载资源后再优化。
- `pnpm lint`：失败，缺少 ESLint 可执行程序；项目需补齐依赖和配置。
- 现有测试集中于 core，Web 保存、路由切换和播放器状态流程缺少自动化覆盖。
- 本轮检查包含源码审查、单元测试、构建和最小移调验证；尚未完成浏览器交互和音频试听验收。
- README、项目规范和帮助文档与实际功能存在版本差异。

### 已发现的关键问题

1. 延迟保存闭包捕获旧源码，却在执行时读取当前曲谱 ID；切谱不取消旧任务，存在串写风险。
2. 存储异常被静默忽略，界面仍更新保存时间。
3. 目录备份按标题命名，同名覆盖；删除缺少对应文件处理，扫描可能重新导入已删除曲谱；清理操作范围覆盖目录内所有 `.jsonc`。
4. 移调同时改变调号和音级，播放叠加偏移。最小验证：C 调 `1` 上移 2 个半音，得到 D 调 `2`，发声由 C4 变为 E4。
5. 解析和保存共用 1 秒防抖；界面可能暂时显示旧解析结果。
6. 曲谱宽度依据窗口而非预览容器；字号没有传入布局计算。
7. 音符调度以秒表示，播放中修改 BPM 的实际效果需要专项验证。

## 3. 版本范围

### 第一阶段：可靠性（P0）

#### R1. 文档保存隔离

- 保存任务绑定文档 ID、源码快照和修订号，不在任务执行时重新推断目标曲谱。
- 切换曲谱、新建、加载示例、移调另存和导入统一经过文档操作入口。
- 切换前完成旧稿保存；取消过期解析任务，禁止旧结果覆盖新文档。
- 页面离开和刷新建立尽力保存与草稿恢复机制，不能仅依赖关闭页面时的异步写入。

验收：编辑 A 后在防抖结束前切到 B，A 的最新内容正确保留且 B 不变；快速连续切换、删除当前谱、移调另存均不串写；刷新后可恢复已落盘草稿。

#### R2. 可验证的保存状态

- 显示待保存、保存中、保存成功、保存失败状态。
- 浏览器保存和目录备份分别报告结果，只有写入成功才更新对应时间。
- 存储失败保留当前编辑内容，提供重试和下载备份入口。
- 统一错误类型及对用户可操作的提示，避免静默吞错。

验收：模拟容量不足、目录权限丢失和写入失败，不误报成功；重试成功后状态恢复；用户仍可导出未保存内容。

#### R3. 目录备份与恢复

- 文件使用稳定 ID 标识，标题只用于展示；增加应用管理文件清单。
- 仅同步变更曲谱，写入排队或合并，防止旧写入覆盖新版本。
- 定义重命名、删除及重新扫描的一致性策略，必要时维护删除记录。
- 解除目录关联与删除应用数据分开；删除操作只处理应用拥有的文件。
- 提供单曲、全量备份导入导出；校验文件结构和版本，定义 ID 冲突处理策略。
- 迁移旧标题文件前保留备份；同名或内容冲突需可见，不能静默覆盖。

验收：同名曲谱互不覆盖；重命名不产生重复曲谱；删除后扫描不复活；不删除目录中的无关文件；备份可导入恢复。

#### R4. 移调语义与序列化

- 区分改变实际音高与改写简谱/指法的操作语义，明确每个界面选项的效果。
- 调号、音级、八度和临时升降号通过共享音高转换函数处理。
- 修复双重偏移，检查负向移调、跨八度及升降音。
- AST 回写源码保留歌词、连音分组、跨小节圆滑线、装饰音和扩展元信息；避免无关改写。

验收：上移 N 个半音只产生 N 个半音的实际偏移；反向操作恢复音乐语义；`parse → serialize → parse` 保持受支持的语义和分组。

#### R5. 语法一致性基线

- 建立单一、可执行的语法规范和测试样例，统一 Parser、CodeMirror 高亮、序列化、在线帮助、用户指南和内置示例。
- 明确标准音符书写顺序：装饰音前缀、升降号、音级、八度、减时线、附点；对已支持的等价顺序可继续兼容读取，标准输出采用一种顺序。
- 修正并验证当前误导性/不一致行为：`'1` 被忽略、`P` 与 `Q` 不一致、`1///` 被截断、重复附点无提示、附点休止不生效、`//` 注释和减时线冲突。
- 明确元信息块、裸旋律的解析规则和默认值；README、帮助及示例必须与解析器接受的形式相符。
- 明确四分音符时值、减时线、单附点、休止符、延长线和拍号的规则；统一解析、节拍校验与播放时值计算，拒绝或诊断未支持的写法，不能静默忽略或截断。
- 保留空白控制 Beam 分组的既有行为，明确空格、Tab、换行及修饰符与音符的关系；格式化、移调和往返不得意外改变分组。
- 区分 Beam、Slur 与同音延长的内部语义和用户说明；本阶段不引入新的显式 Tie 语法。
- 澄清当前歌词规则：歌词按有效的普通发声音符消费；休止符、延长线、换气和倚音不消费歌词。更新与实际行为一致的示例和说明。
- 在语法用例中覆盖升降号、八度、装饰音、歌词、括号、行尾、非法/重复修饰符和错误位置；为规范示例建立解析器回归测试。

验收：每个帮助和示例中的语法用例都能通过解析；编辑器高亮与解析 token 一致；非法或超出支持范围的输入显示位置明确的错误/警告；不存在静默吞字符、截断时值或文档承诺与实际结果不符；既有合法曲谱的含义不因格式规范化发生变化。

### 第二阶段：核心编辑体验（P1）

#### E1. 解析与保存分离

- 解析使用约 300ms 独立防抖，保存使用独立策略。
- 播放前确保解析结果对应当前源码；过期结果不得用于播放。
- 保留错误下划线和悬浮说明，增加点击诊断定位源码。
- 增加点击小节定位源码，统一源码与预览的映射。

验收：编辑反馈不等待存储完成；刚输入后立即播放使用最新内容；诊断定位正确且不打断输入。

#### E2. 容器响应式排版

- 使用预览容器实际宽度计算布局。
- 字号进入布局配置，同时影响音符间距、行高及歌词位置。
- 处理密集小节、长歌词与跨行圆滑线。
- 移动端提供编辑/预览切换，避免过窄分栏。

验收：拖动分栏、调整字号及改变视口后布局更新；代表性密集曲谱不发生符号或歌词重叠；移动端核心操作可用。

#### E3. 曲谱管理

- 标题搜索、最近编辑排序、复制曲谱。
- 明确新建空白谱与从示例创建的区别。
- 标题重命名同步源码，避免后续解析覆盖新标题。

验收：重命名后再次编辑标题保持一致；复制产生独立 ID；搜索与排序反映最新数据。

### 第三阶段：练习能力（P1）

#### P1. 统一播放时间模型

- 以拍数或可精确换算的音乐时间表示调度事件，音频输出阶段再换算。
- 统一音符、节拍器和倒计时的时间基准。
- 练习速度倍率与曲谱原始 BPM 分离。
- 明确初始化、预热、播放、暂停、停止、失败的状态转换和清理责任。
- 播放失败提供界面反馈，防止重复初始化和过期回调。

验收：变速后音符、节拍器和高亮保持同步；暂停恢复不从头播放；停止和切谱后旧回调不影响新谱。

#### P2. 选段练习

- 从指定小节开始播放。
- A/B 小节范围循环，明确范围包含关系和边界行为。
- 播放自动跟随，用户手动浏览时允许暂停跟随。
- 循环入口复用倒计时及练习速度设置。

验收：选段不播放范围外音符；跨边界延音、休止和装饰音有明确策略；重复循环无累计漂移；高亮与实际播放位置一致。

## 4. 架构实施原则

1. 保留 Zustand，按文档、曲谱库、播放、OCR、界面职责拆分模块；播放器、存储队列等副作用由服务管理。
2. 组件使用 selector 订阅必要状态，限制高频音符高亮更新的渲染范围。
3. Parser 和 Layout 保持纯数据计算；音乐语义共享，音频适配层负责副作用。
4. 存储接口统一返回可验证结果；增加数据格式版本、运行时校验及迁移能力。是否采用 IndexedDB 以一致性和性能需求为依据。
5. AST 与源码保留映射；格式化或移调不能破坏空格控制的连音分组。
6. 性能优化先测量；区分初始加载与音频懒加载资源，不仅为了消除 chunk 提示拆包。

## 5. 依赖顺序与测试

- R1/R2 是文档操作和可靠导入的基础，先于 E1、E3 完成。
- R3 基于可验证存储接口；旧目录迁移必须有恢复路径。
- R4 与统一音乐时间模型应先建立语义用例，再扩展 P2。
- E2 可在保存和播放改造期间独立实施。
- 每个阶段补充相应回归测试，避免最后集中补测。

必需的质量门禁：

- 补齐 ESLint 依赖与 TypeScript/React 配置。
- PR 自动运行 lint、core 测试、Web 测试和生产构建。
- Web 测试覆盖保存竞态、存储失败、路由切换、导入及播放状态转换。
- 浏览器端验证编辑→保存→刷新恢复、移调另存、目录备份、选段循环。
- 对典型曲谱进行排版视觉检查和音频试听。
- 检查现有 4 项跳过测试的原因，明确恢复或保留理由。
- 更新 README、架构说明、项目规范、在线帮助和语法指南；文档中的示例应能被解析器验证。

## 6. 本版暂缓

- OCR 重新开放：当前识别入口隐藏、设置入口禁用。后续需一起完成配置、请求取消、校对和导入保存流程。
- 图片/PDF 导出。
- 云同步、在线分享和多声部。

## 7. 语法设计评审边界

v0.7.0 包含 R5 语法一致性基线：修复文档、解析器、编辑器和序列化之间的差异；定义规范写法和诊断；保持既有合法曲谱的音乐含义。

歌词按相邻旋律块绑定、显式延音写法、速度单位扩展、弱起小节和其他新增语法属于语义变更候选，暂列 v0.7.1 待确认计划。不得在 v0.7.0 中悄然改变旧谱解释。
